### 章節重排

封面宣告四節，但頁面順序原本是混的。重排為：

```
一、主採範疇      量體 → 十四大類與 AI 可協助比例 → 文書只是表象 → 品質異常個案 → 核色判斷鏈
二、AI 能協助到哪裡  六個結構性原因 → AI 幫不上與需人拍板的事
三、已導入的 AI 工具  已接手的與接不了的 → 四支 skill
四、結論與建議
```

### AI 定位的改寫

原本多處寫成「AI 可代勞程度全部評為低」，讀起來像「AI 沒用」；
改為團隊自己的 10–15% 協助估算，訊息定調為**協作而非取代**：

- 封面第二節：「AI 可代勞程度分析」→「AI 能協助到哪裡、不能代替什麼」
- 量體頁的「100% 全數評為低」→「10–15% AI 可協助的整體估算，其餘靠人」
- 「為什麼十四類全評為低」→「AI 為什麼只能協助、不能代替」
- 結論頁標題→「AI 是協作者，不是替代人力的方案 — 行政步驟壓縮 10–15%，決策仍須人拍板」
- 新增四條結語帶（第 8、9、10 頁與原第 11 頁的訊息），落在「人按下確認鍵」「誰來扛」等處

## 四、主副料採購 — AI 導入評估（integrated_out.pptx，2 頁）

把主採與副採合在一起看，回答一個問題：**為什麼工時省得下來，人力卻減不掉。**
原為 5 頁（封面＋四節），2026-09-11 依需求壓成 2 頁，無封面 —— 當作兩頁式 handout。

```
① 現況 —— 量體、已導入的工具，以及它們接手到哪裡
   4 個數字（25 類／10 位／12.6%／9 項）＋ 主採 5 支 skill、副採 4 個介入點對照
   ＋ 紅底警語：25%／40% 別讀錯
② 為什麼工時省得下來，人力卻減不掉 —— 六個共通原因
   6 張卡片 ＋ 深藍關鍵句 ＋ 三條建議
```

### 六個共通原因（兩份簡報的交集）

① 是「議定」不是「查詢」／② 等待不會因 AI 變快／③ 要看實物才能拍板／
④ 溝通載體不在系統裡／⑤ 承諾與責任要人來扛／⑥ 資料會回頭改寫上一輪的答案

### 三個推算值（皆在頁面上標示算式）

| 數字 | 怎麼來的 |
|---|---|
| **12.6%** | 主採十四類 AI 可協助比例（5–25%）依占比加權平均；落在該簡報自述的「約 10–15%」內 |
| **25%** | 主採已有 skill 對應的類別占比相加（10.035＋10＋5） |
| **40%** | 副採四個潛在介入點所在類別占比相加（20＋5＋10＋5） |

第 1 頁的紅底警語專門說明：25% 與 40% 是「工具碰得到的類別」占多少，
**不是「可以被取代的工時」** —— 工具接手的是類別裡的登錄與比對步驟。

壓成 2 頁後，兩頁的來源行各需兩行才容得下兩份來源的口徑聲明，
因此使用 `source2()`（y=7.04、高 0.38）而非家族慣用的單行 `source()`。

## 檔案

| 檔案 | 用途 |
|---|---|
| `gen.py` | 產生主採三頁並註冊進 package |
| `renumber.py` | 更新封面目錄與後續章節編號 |
| `fucai_v2.py` | 重新排版／修順並輸出獨立的副採簡報 v2 |
| `zhucai_v2.py` | 統一主採簡報的兩套版面、重排章節、改寫 AI 定位 |
| `integrate.py` | 由兩份簡報的數字產出主＋副整合版（全新 5 頁） |
| `qa.py` | 幾何檢查：超出版面、實質重疊（排除設計上的巢狀面板）、文字溢出估算 |
| `build.sh` | 兩份一起跑完並驗證 |
| `fucai_src_20260907_Q1.pptx` | 副採來源簡報，使用者重整版（build 時複製為 `q1.pptx`） |
| `zhucai_src_20260907_G.pptx` | 主採來源簡報，使用者重整版（build 時複製為 `g1.pptx`） |

## 使用方式

```bash
# src.pptx = 業務簡報原檔；q1.pptx = 副採重整版原檔
bash build.sh
python3 qa.py
```
