# 主採／副採章節投影片產生器

在既有的《業務工作範疇說明》簡報（V6，2026-09-02 版，15 頁）中，插入兩個新章節共七張投影片：

- **三、主採**（3 頁）— 由 `gen.py` 依《主採工作內容分類與 AI 可行性分析》綜合分析表產生
- **四、副採**（4 頁）— **直接匯入**副採自製的《V6副採工作範疇簡略說明》（2026-09-07，人力編制 3 位）

並將原本的「三、A 部現況」「四、結論」順延為「五」「六」，同時更新封面目錄。產出 22 頁。

## 為什麼副採用「匯入」而非重新產生

該來源簡報已使用與主簡報完全相同的設計語彙（同版面、同色票、同字體、同左側直條），
且其數字為 ERP 實績盤點值。直接匯入原始 slide XML 可以零轉錄風險地保留原始數據與版面，
只做三處必要調整：

1. 眉標改寫為「四、副採｜系統操作」等，使其歸屬於本簡報的第四章
2. 補上明確的白色背景（來源簡報的背景繼承自其 layout）
3. 「見上一頁對照表」改為「見本章『系統操作』頁對照表」（併入後頁序改變）

另有一處版面修正（`_fix_stat_row`）：來源簡報「系統操作」頁的四個數字卡片
第一、二張重疊 0.17"、三個間距不一（-0.17 / 0.37 / 0.10），第二張的標籤縮排也與其他三張不同。
併入時已重新等分排列並統一縮排。

## 檔案

| 檔案 | 用途 |
|---|---|
| `gen.py` | 產生主採三頁、匯入副採四頁，並完成 package 註冊 |
| `renumber.py` | 更新封面目錄，並將後續章節編號順延 |
| `build.sh` | 解壓兩份來源 → 產生／匯入 → 重新打包 → 驗證，一次跑完 |
| `fucai_src_20260907.pptx` | 副採來源簡報（build 時複製為 `fucai_src.pptx`） |

## 使用方式

把主簡報放在與腳本同一層、命名為 `src.pptx`，副採簡報命名為 `fucai_src.pptx`，然後：

```bash
bash build.sh      # 產出 out.pptx
```

## 設計語彙（取自原簡報）

- 版面 13.333" x 7.5"；內容區 x=0.62、寬 12.09；左側 0.16" 深藍直條
- 色票：`1C4F8F` 深藍／`2A78D6` 亮藍／`0B0B0B` 標題黑／`454441` 內文／`898781` 註記
  ／`F4F6F9` 面板／`E8F1FC` 結語底／`D03B3B`＋`FDEFEF` 強調
- 字級：眉標 12.5pt、標題 22-25pt、區塊標 12.5pt、卡片標 10.5pt、內文 9-10pt、來源 8.5pt
- 字體：微軟正黑體
- 每頁結構：眉標 → 標題 → 分隔線 → 內容 → 淺藍結語帶「→ …」→ 灰色資料來源

## 數字口徑

各頁的資料來源行完整保留來源文件自述的樣本與估算限制，未經淡化：

- 主採：樣本僅一人信箱可見範圍、非三人完整信箱、不含微信；占比為關鍵字分類估算值
- 副採：ERP PO 為系統盤點實績（僅涵蓋 GU 相關供應商代碼 TMKA／CJYA／CMKA／CMZA）；
  Shipping Monitor key-in 次數為推算值；11 大類佔比為體感估計
