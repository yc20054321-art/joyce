# 主採／副採投影片腳本

產出**兩個各自獨立的檔案** —— 副採刻意不併入業務簡報。

| 產出 | 頁數 | 說明 |
|---|---|---|
| `out.pptx` | 18 | 《業務工作範疇說明》＝ 原 15 頁 ＋ 新增「三、主採」3 頁 |
| `fucai_out.pptx` | 5 | 《V6副採工作範疇簡略說明》＝ 副採自製版，修正三處後獨立成檔 |

## 一、業務工作範疇說明（out.pptx）

在原簡報（V6，2026-09-02，15 頁）中插入「三、主採」三頁，
依《主採工作內容分類與 AI 可行性分析》綜合分析表產生：

1. 工作範疇與量體 —— 14 類、1,993 封信，AI 可代勞程度全評為「低」
2. 為什麼十四類全評為「低」—— 六個共通結構性原因
3. AI 已接手的與接不了的 —— 三支現成 skill vs. 移染／白汙／色差判定實例

原本的「三、A 部現況」「四、結論」順延為「四」「五」，封面目錄同步更新為五項。
**此檔不含副採章節。**

## 二、V6副採工作範疇簡略說明（fucai_out.pptx）

以副採自製版（2026-09-07，人力編制 3 位）為準，獨立成檔。原始 slide XML 保留不動，
只修正三處：

1. **「系統操作」頁的四個數字卡片版面** —— 來源檔中第一、二張重疊 0.17"、三個間距
   不一（-0.17 / 0.37 / 0.10）、第二張標籤縮排 0.37" 而其他三張為 0.10"。
   已重新等分排列（間距 0.20"）並統一縮排。
2. **封面副標「(人力編制-3位)」** —— 原本未指定字級、且用主題色 bg2@75%，
   在深藍封面上不保證可讀。改為與姊妹簡報封面副標一致的 27pt / `C9DFF7`。
   **這一行本身保留 —— 人力編制要留在封面。**
3. **「見上一頁對照表」** —— 實際指向三頁前，改為「見『系統操作』頁對照表」。

## 檔案

| 檔案 | 用途 |
|---|---|
| `gen.py` | 產生主採三頁並註冊進 package |
| `renumber.py` | 更新封面目錄與後續章節編號 |
| `fucai_standalone.py` | 修正並輸出獨立的副採簡報 |
| `qa.py` | 幾何檢查：超出版面、實質重疊（排除設計上的巢狀面板）、文字溢出估算 |
| `build.sh` | 兩份一起跑完並驗證 |
| `fucai_src_20260907.pptx` | 副採來源簡報（build 時複製為 `fucai_src.pptx`） |

## 使用方式

```bash
# src.pptx = 業務簡報原檔；fucai_src.pptx = 副採原檔
bash build.sh
python3 qa.py
```

## 設計語彙（取自原簡報）

- 版面 13.333" x 7.5"；內容區 x=0.62、寬 12.09；左側 0.16" 深藍直條
- 色票：`1C4F8F` 深藍／`2A78D6` 亮藍／`0B0B0B` 標題黑／`454441` 內文／`898781` 註記
  ／`F4F6F9` 面板／`E8F1FC` 結語底／`D03B3B`＋`FDEFEF` 強調
- 字級：眉標 12.5pt、標題 22-25pt、區塊標 12.5pt、卡片標 10.5pt、內文 9-10pt、來源 8.5pt
- 字體：微軟正黑體
- 每頁結構：眉標 → 標題 → 分隔線 → 內容 → 淺藍結語帶「→ …」→ 灰色資料來源

## 數字口徑

各頁資料來源行完整保留來源文件自述的限制，未經淡化：

- 主採：樣本僅一人信箱可見範圍、非三人完整信箱、不含微信；占比為關鍵字分類估算值
- 副採：ERP PO 為系統盤點實績（僅涵蓋供應商代碼 TMKA／CJYA／CMKA／CMZA）；
  Shipping Monitor key-in 次數為推算值；11 大類佔比為體感估計
