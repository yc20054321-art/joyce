# 大貨主副料空/陸運控管表 —— 自動產生方案

回應 mail thread「大貨相關主副料空運快遞費用」中提到的：

> 1. 採購製控管表：由業務於進單通知信上輸入資料，並透過 Claude Code 捉取、建立及持續更新相關資訊。
> 2. 空運需求確認：由採購依 TA 時程主動向工廠確認是否需要空運及需求數量。

現在每次都是 Anita 手工整表、手工反黃、手工回信。以下把它拆成三段，各段都有現成做法。

---

## 一、整件事其實是三段，不要混在一起想

| 段 | 在做什麼 | 誰在做 | 能不能自動 |
|---|---|---|---|
| A 取數 | 從 BIS / 進單通知信撈出 STYLE、成衣件數、CRFP、EXP、ETC、運輸方式 | 業務填、Anita 整 | **可以**，看下面四條路 |
| B 判斷 | 算決策日、決定誰決策、決定要不要反黃 | 人腦 + Excel 手工上色 | **完全可以**，規則是死的 → 本資料夾的程式 |
| C 催辦 | 到期前發信問產區/主採，收回覆、更新結論 | 手工發 mail | **可以**，排程寄信 |

B 段是最好啃、CP 值最高的一段：規則已經在 mail 裡講清楚了，
「成衣量 > 1 萬件」「決策 due day = 出布期前兩週」，程式一寫就永遠不會忘記上色、不會算錯兩週。
**建議先把 B 做掉，A 先接受半自動（貼 CSV），C 之後再加。**

---

## 二、A 段取數的四條路（由淺到深）

### 路線 1：BIS 匯出 → 貼 CSV → 跑程式（今天就能用）
Anita 現在已經會從 BIS 撈資料。把撈出來的欄位另存成 `orders.csv`，跑一行指令就得到反黃好的 xlsx。
- 優點：零 IT 資源、今天就能上線、規則從此統一。
- 缺點：還要人去按匯出。
- **這就是本資料夾實作的版本。**

### 路線 2：Power Automate 讀進單通知信 → 自動落表
公司是 Microsoft 365（Outlook/Exchange），可以用 Power Automate 免費流程：
1. 觸發：收到主旨含「進單通知」的信。
2. 動作：抓信中表格 / 附件 Excel，寫進一份 SharePoint 或 OneDrive 上的共用 Excel。
3. 排程：每天早上跑一次判斷，把反黃結果寄給主採 + 產區。
- 優點：業務不必改習慣，照常發進單通知信即可。
- 前提：**進單通知信的表格格式要固定下來**（欄位名稱、順序不能每個業務不一樣）。
- 這是投資報酬率最高的一條，但要先跟業務端談定格式。

### 路線 3：BIS 直接排程匯出（要 IT）
請 IT 在 BIS 開一支排程報表，每晚把「已進單 + 出口期在未來 N 個月」的款號丟到共用資料夾，
程式每天自動吃該檔。這條最乾淨、最不會有人為漏填，但要排 IT 工單。

### 路線 4：Claude Code 直接讀信（mail 裡原本的想法）
把每封進單通知信丟給 Claude Code，讓它把非結構化的文字/表格轉成本資料夾的 CSV 欄位，再跑判斷。
- 優點：格式再亂都能吃，不用先統一格式。
- 缺點：**AI 讀出來的數字必須有人抽查**，不能直接進決策；適合當路線 2 的補漏（格式沒統一前的過渡）。
- 用法：讓它照 `orders_sample.csv` 的欄位輸出，再跑 `generate.py`。

**建議路徑：現在走路線 1 → 同時去談進單通知信格式 → 談成後升級路線 2 → 有 IT 資源再升級路線 3。**

## 三、本資料夾（B 段）已經做好的東西

```
air_control/
├── rules.py            反黃規則，所有門檻集中在檔案最上面，要改直接改數字
├── generate.py         主程式
├── orders_sample.csv   輸入格式範例（用 mail 附件裡的真實款號建的）
└── out/                產出
    ├── 控管表.xlsx     反黃已上色、有篩選、凍結窗格，可直接當附件寄出
    ├── 控管表.csv      給 BI / 其他系統再吃
    └── 催辦.md         今天該問誰、該問什麼，貼進 mail 就能寄
```

### 怎麼跑

```bash
pip install openpyxl
cd air_control
python3 generate.py orders_sample.csv                      # 用今天當基準日
python3 generate.py orders.csv --outdir out --today 2026-08-11   # 指定基準日
```

### 程式幫你算什麼

| 產出欄位 | 規則 |
|---|---|
| 決策時間點 | 空/陸運 ETC − 14 天 |
| 決策人員 | 成衣件數 > 10,000 → 產區；否則 主採/大貨MD |
| 主要確認 | 空運 →「是否需全量走AIR?」；陸運 →「是否需全量走卡車?」 |
| 結論 | 海運 IN FTY 晚於成衣 EXP →「無法海運出布(成衣交期急迫)」；還有餘裕則提示可評估改海運 |
| 超標金額 | (空運單價 − $0.24) × 實打，只列超出的 |
| 反黃 | 成衣件數 > 10,000 且走空/陸運 → 整列黃底；決策日剩 3 天內轉粉紅底 |
| 狀態 | 距決策日剩幾天 / 逾期幾天 |
| 警示 | 缺 ETC、缺 EXP、走空運卻沒單價等，直接點名要誰補 |

規則產出的日期跟 Anita 手工表對得起來：
227H046B → 決策日 8/31、227H059A/F → 8/17，與 mail 內容一致。

### 要改門檻就改 `rules.py` 最上面

```python
QTY_THRESHOLD = 10_000       # 成衣件數門檻
DECISION_LEAD_DAYS = 14      # 決策日 = ETC 前幾天
QUOTED_RATE = 0.24           # 報價已含的標準單價
URGENT_WINDOW_DAYS = 3       # 剩幾天內轉粉紅催辦
```

## 四、C 段催辦怎麼接（下一步）

`out/催辦.md` 已經是可以直接寄的內容。要全自動的話兩個選擇：

- **Power Automate 排程**：每天早上 8:00 跑，把催辦清單寄給該負責的主採 / 產區，逾期的副本給大貨 Leaders。
- **Outlook 規則 + 手動**：先讓 Anita 每天早上跑一次程式、貼一封信，跑順了再自動化。

建議先手動跑兩週，確認反黃結果跟大家的判斷一致，再接自動寄信 —— 免得規則沒調好就開始每天亂發信。

## 五、要讓這件事真的自動化，需要先確認的三件事

1. **進單通知信的欄位格式能不能統一？** 這是路線 2/3 的前提，也是投資報酬率最高的一步。
2. **成衣件數在配布列要不要重複填？** 目前程式的作法是配布沿用同 STYLE 主布的件數，若實際規則不同要調整。
3. **「結論」欄要不要回寫？** 產區/主採決策後的回覆，是要人工填回 Excel，還是要在系統裡留紀錄以便日後查核空運費用。
